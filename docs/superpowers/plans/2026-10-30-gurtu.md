# Gurtu Implementation Plan

> **For agentic workers:** Use this task list as the implementation checklist. The user's master build prompt is the source of truth for requirements and exact acceptance behavior.

**Goal:** Build the private, multilingual Gurtu family memory website with strict household-level database privacy.

**Architecture:** A responsive React/Vite/TypeScript frontend uses Supabase Auth and RLS-backed PostgreSQL. Authenticated Supabase Edge Functions validate OpenAI outputs and execute only confirmed, permitted operations. Cloudflare Pages serves the static frontend.

**Tech Stack:** React, Vite, TypeScript, React Router, Supabase JS, Supabase PostgreSQL/Edge Functions, Zod, OpenAI Responses API, `gpt-transcribe`, Vitest, Playwright, and pgTAP.

---

## File ownership map

- `src/app/`, `src/components/`, and `src/features/`: accessible application shell, auth, home, remember, ask, memories, history, lists, and calendar screens.
- `src/lib/` and `src/types/`: Supabase client, domain types, dates, people matching, and validation.
- `supabase/migrations/`: relational schema, helper functions, indexes, constraints, and RLS.
- `supabase/functions/`: authentication-scoped transcription, interpretation/execution, and retrieval.
- `supabase/tests/`: synthetic-data database/RLS tests.
- `scripts/`: secure interactive family provisioning and secret scanning.
- `tests/`: unit and browser-level tests.
- `docs/`: run, architecture, database, security, deployment, and family setup instructions.

## Tasks

1. **Foundation** — add the Vite/React/TypeScript app, dependencies, environment placeholders, Cloudflare Pages files, route shell, typography/colors, and the two reference screens.
2. **Domain validation** — add failing-first unit tests and implement action schemas, alias matching, timezone-safe event parsing/formatting, and the 24-hour home event predicate.
3. **Database and isolation** — migrate the family/household/profile/people/memory/location/list/event/access/activity schema; enable RLS everywhere; add atomic request limiting and synthetic pgTAP isolation tests.
4. **Authentication** — implement login, reset-password, session restoration, protected routes, logout, and a secure five-account provisioning script without hard-coded personal details.
5. **Core screens** — connect home, remember, ask, memories, history, lists, and calendar to Supabase through user-scoped clients and show honest empty/loading/error/success states.
6. **AI and voice** — add authenticated Edge Functions, OpenAI Responses structured parsing, in-memory audio transcription, confirmation and execution, evidence-grounded answers, request limits, and idempotency.
7. **Quality and handover** — run typecheck, lint, unit/browser/database tests, dependency and secret scans, visual QA against both supplied screenshots, then document blockers and verified deployment state.

## Execution constraints

- Use synthetic fixtures only; never write test data to a production database.
- Do not put credentials in source, docs, test fixtures, or Git. `.env` stays local and ignored; `.env.example` contains placeholders only.
- Do not create family accounts or people until the user supplies their actual details.
- Do not deploy an unusable login shell. Cloudflare deployment waits for the Supabase URL/publishable key and repository integration.
- The repository remains private. The browser-based GitHub sign-in is pending; local GitHub CLI credentials are invalid.
